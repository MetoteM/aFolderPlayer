# Android-прототип Звука — 0.8.3-preview.2

Ветка prerelease/zvuk-spike. aFolderPlayer 0.8.3/code 40, AFP Online 0.1.1/code 2.
Этот опыт не является интеграцией Сбер ID и не доказывает работу с реальной подпиской.

## Как проверить

1. Установить APK плеера и AFP Online из предварительного выпуска.
2. Открыть «Расширения → Онлайн → Прототип Звука», либо отдельную иконку AFP Online.
3. Через «Открыть Звук для входа» войти в собственный аккаунт на стороне сервиса.
4. В эксперименте используется ручной ввод токена собственной веб-сессии; инструкция доступна на экране. Токен не передавать в чат, issue или GitHub.
5. Нажать «Подключить и проверить». Затем проверить поиск и первые 20 треков коллекции.
6. Выбрать трек и подтвердить пробное воспроизведение. Источник и наличие потока проверяются отдельно от сессии.
7. Проверить остановку, выход с экрана и отключение сессии. Меню результата содержит только состояния этапов.

Сессия хранится только в памяти экрана и не восстанавливается после уничтожения Activity.
После закрытия экрана может потребоваться повторный локальный ввод. Экран защищён от снимков и автозаполнения поля токена. Пароль Сбера в AFP Online не вводится.

## Границы

- Поиск, профиль, коллекция и поток — только чтение, без изменений аккаунта.
- Постоянный токен используется только в запросах к HTTPS API zvuk.com; на CDN он не передаётся.
- Нет автоматического входа, извлечения cookies, обновления сессии, обхода защиты или DRM.
- Нет автоматического fallback качества: запрашивается mid. Доступность определяется реальным ответом сервиса.
- Пробный проигрыватель MediaPlayer работает только на открытом диагностическом экране, запрашивает аудиофокус и освобождается при уходе/потере фокуса.
- Это временный диагностический проигрыватель, не общая очередь приложения. Фон, часы и единая очередь остаются отдельным этапом после подтверждения работающего доступа. Основной PlaybackService не менялся.
- Показ начала воспроизведения не считается полным успешным прогоном песни; в результате отдельно отмечается завершение.

## 0.8.3-preview.3 — раздельная проверка API

После подтверждённого отказа HTTP 418 на шаге «Подключить и проверить» профиль перестал быть единственным входом к диагностике музыки. AFP Online 0.1.2/code 3 добавляет явную кнопку «Проверить музыкальный API отдельно». Она делает один независимый read-only запрос коллекции с введённым пользователем токеном, без повторов запроса профиля. Успех этой проверки означает только читаемый ответ музыкального API, не подтверждение личности или подписки. Отказы музыкального API также останавливают проверку.

В ошибке теперь указан этап: профиль, музыкальный API, коллекция, поиск или получение потока. После отказа профиля токен можно не копировать заново, пока экран не уничтожен. Если он утрачен после закрытия экрана — ввести локально ещё раз. Обновляется только AFP Online; плеер из preview.2 остаётся прежним.

Отказ HTTP 418 самого сервиса не объявляется исправленным. Доступ к реальному аккаунту и потокам должен подтвердить последующий опыт на устройстве.

Проверки обновления: исходники b53e65cd4d9316c183392118e0a9d9615dac8cf2, Android CI 38748507510 — success. Добавлены отдельные тесты запроса музыкального API и UI-сценария, где профиль не прошёл проверку. С реальным аккаунтом новая проверка пока не выполнена.
