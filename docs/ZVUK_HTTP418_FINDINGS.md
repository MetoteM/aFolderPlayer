# HTTP 418: проверка после опыта пользователя

15 октября 2026. Ветка prerelease/zvuk-spike. Исправление доступа не подтверждено; новый APK по этому исследованию не публикуется.

## Факты

- Пользователь подтвердил HTTP 418 и при проверке профиля, и при независимой проверке музыкального API в AFP Online 0.1.2.
- Пользователь подтвердил: на том же телефоне и в той же сети музыка через сайт zvuk.com воспроизводится.
- Это исключает общую недоступность сайта в данной проверке, но не доказывает корректность перенесённого токена и не устанавливает причину отказа API.
- Из облачной среды без аккаунта выполнены два ограниченных запроса: GET /api/tiny/profile и POST /api/v1/graphql с запросом __typename. Оба вернули HTTP 418, Content-Type text/html, Server nginx, заголовок страницы «Ошибка доступа», а не JSON.
- На странице отказа есть сообщение о защите от автоматизированных запросов и общая рекомендация проверить VPN/блокировщик либо обратиться в поддержку. Это общий текст, не доказательство причины на устройстве пользователя. Адрес и идентификатор запроса в проект не сохраняются.
- Тело ответа с телефона неизвестно: текущий клиент не читает errorStream и показывает общее сообщение. Нельзя выдавать облачный ответ за точную копию ответа телефона.

## Сопоставление транспорта

Проверен zvuk-music commit ed491f61bc7b18c9f327017a8a87d9fe183022a7, utils/request.py и request_async.py. Автор классифицирует HTTP 418 и HTML-ответы как BotDetectedError, в комментарии указывает ServicePipe. Это свидетельство существующего клиента, не официальное объяснение нашего конкретного запроса.

Наш клиент использует HttpURLConnection, собственный User-Agent, Accept application/json и X-Auth-Token, без браузерного cookie-хранилища. Сторонняя библиотека имеет иной набор заголовков и транспорт. Обнаруженное различие само по себе не устанавливает, какой параметр вызывает отказ. Состояние браузера нельзя считать автоматически переданным одному токену.

В журнале автора MA-провайдера есть отдельные изменения транспорта, связанные с HTTP 418 для текстов и потоков: https://github.com/trudenboy/ma-provider-zvuk-music/blob/dev/CHANGELOG.md . Проверен commit провайдера 3499283a0334318d9c86aaa566d59c51cfa2b266.

## Что нельзя считать установленным

Не подтверждены: недействительность токена, отсутствие подписки, геоблокировка, конкретный недостающий заголовок, обязательность cookie или иной конкретный признак проверки клиента. HTTP 418 без поддерживаемой схемы/трассировки не позволяет выбрать одну из этих причин. Успешное воспроизведение сайта не подтверждает доступ независимого APK к музыкальному API.

## Следующий технический шаг

1. Подтвердить поддерживаемую схему запросов/передачи сессии для стороннего клиента. Регистрация собственного Сбер ID сама этого не решает.
2. Для диагностики errorStream использовать только ограниченное чтение и классификацию ответа: этап, статус, тип JSON/HTML, известная страница ограничения, наличие Retry-After. Не показывать и не публиковать произвольное тело, токены, cookies, профиль, адрес пользователя, request ID или подписанный URL.
3. Разделять ограничения веб-доступа, отказ авторизации, недостаточность прав и ошибку схемы API. Не объявлять HTTP 418 ошибкой пароля/подписки.
4. При отказе не повторять запросы автоматически. Новый APK должен либо содержать проверенное изменение совместимости, либо явно предлагаться как диагностический, а не исправляющий доступ.
5. Решение о рабочем коннекторе принимать после успешной проверки сессии и фактического воспроизведения на устройстве. Сейчас оснований для стабильного релиза нет.

Токены пользователя не запрашивались и не использовались. Защиты сервиса не обходились. В поддержку от имени пользователя ничего не отправлялось.
