# Регистрация LoginSDK для aFolderPlayer

После пробы preview 3 на телефоне Яндекс показал 500. Точная серверная причина неизвестна: скриншот не позволяет установить её и не подтверждает конфликт с уже открытой сессией.

В preview 3 использовался публичный Client ID веб-эксперимента. Собственной регистрации Android-пакета aFolderPlayer и сертификата у этого клиента нет. Для LoginSDK требуется собственная регистрация. В preview 4 запуск без такой конфигурации заменён объяснением и переходом к рабочей странице входа. Рабочий токен не удаляется.

## Параметры для регистрации

Официальная инструкция: https://yandex.ru/dev/id/doc/ru/mobileauthsdk/android/3.1.3/sdk-android

Регистрация приложения: https://oauth.yandex.ru/client/new/id/

| Поле | Значение для тестовой линии |
|---|---|
| Название | aFolderPlayer Online |
| Платформа | Android |
| Android package name | dev.alex.afponline.yandexlab |
| SHA256 Fingerprint | 36:EF:DE:60:39:67:28:2D:EB:D9:76:20:0C:92:AC:F4:6B:68:14:4B:27:04:D6:19:30:EB:DD:9C:17:13:02:CD |
| Сайт проекта | https://github.com/MetoteM/aFolderPlayer |

Это параметры расширения, которое выполняет вход, а не основного плеера. Отпечаток относится к оригинальному сертификату, которым подписаны выдаваемые APK. Нового ключа создавать не нужно. Случайно подписанный CI-debug APK не соответствует этому отпечатку.

Не подставлять вымышленную ссылку Google Play. Если форма требует опубликованное приложение, уточнить у Яндекса условия регистрации неопубликованного клиента.

После регистрации нужен публичный Client ID (32 шестнадцатеричных символа). Пароль аккаунта, Client Secret и токен присылать не нужно.

## Сборка после регистрации

В сборке расширения задать Gradle property `yandexSdkClientId`, например:

```sh
bash gradlew :online:assembleDebug -PyandexSdkClientId=CLIENT_ID_ИЗ_РЕГИСТРАЦИИ
```

Свойство включает SDK и задаёт его manifest placeholders. Без свойства кнопка объясняет настройку и предлагает рабочую страницу входа. Перед установкой APK должен быть подписан оригинальным ключом проекта.

Само получение Яндекс ID не гарантирует права к Музыке. Токен SDK проверяется запросом account/status и чтением коллекции; только после успешной проверки он заменяет сохранённую сессию. При отсутствии музыкальных прав требуется отдельное согласование доступа; права профиля не заменяют музыкальные.

## UI preview 4

Каталог Яндекс Музыки, экран аккаунта и страница входа учитывают status/navigation bars и вырезы экрана. Исходные отступы сохраняются, повторная доставка insets их не накапливает. Есть регрессионные тесты портретных и боковых системных панелей.
