# Яндекс preview 3: исправления после проверки на телефоне

Ветка: prerelease/yandex-spike. Main и стабильный релиз не изменены.

Плеер 0.8.4-yandex.3 (44), расширение 0.2.0-yandex.5 (8). Установить оба APK поверх предыдущего тестового комплекта с оригинальной подписью проекта. Стабильный плеер сохраняется отдельно.

## Поведение

- Текущий онлайн-трек представлен в действиях плеера: меню текста, поиск/импорт/свой текст и распознавание доступны по стабильному ID. Файловые действия «год альбома» и добавление в локальный плейлист исключены из меню онлайн-песни.
- Обложка берётся из metadata конкретной записи очереди, а не из агрегированных metadata контроллера, которые могут отставать на один трек. Асинхронный результат проверяется по ID и поколению загрузки. Файлы кэша записываются через временный файл с переименованием.
- Длительность из каталога сохраняется в очереди и показывается до разбора аудиопотока.
- В каталоге видна кнопка «Войти / аккаунт». Вход запускается из плеера; искать значок второго приложения не требуется.
- Подключён официальный LoginSDK 3.1.3. Нативный вход запускается отдельной кнопкой; SDK сам выбирает установленное приложение/браузер. Это эксперимент с существующим публичным клиентом: нет собственной зарегистрированной интеграции с музыкальными правами. Успех на устройстве не подтверждён. Полученный токен сохраняется только после успешных account/status и чтения коллекции; отказ/отмена не стирают рабочую сессию. Страница авторизации остаётся альтернативой.
- Плейлисты открываются нажатием на строку с подписью «Открыть». Можно запустить загруженные треки; доступны следующие страницы по 50. Недоступные записи исключаются из подготовленной очереди. Чтение не изменяет плейлисты на Яндексе.
- «Сеть и качество» в каталоге: только Wi-Fi; отдельное качество MP3 для Wi-Fi и мобильной/другой сети. Экономное выбирает минимальный, максимальное — максимальный доступный полный MP3. Preview и зашифрованные форматы исключены. Качество меняется при следующем открытии потока.
- Ограничение Wi-Fi проверяет открытие/чтение аудио, запросы каталога и загрузку обложек, включая уведомление. Уже полученный буфер может доиграть. Неподтверждённый транспорт VPN блокируется в режиме Wi-Fi. После возврата сети кнопка воспроизведения повторно подготавливает поток после ошибки.

## Передача данных

Яндексу уходят авторизация, запросы каталога/поиска, идентификаторы запрошенных треков/обложек и обычные сетевые данные соединения. События прослушивания, автоматические лайки/дизлайки и локальная библиотека не отправляются нашим кодом. Поток всё равно раскрывает сервису факт запроса трека; обещание анонимности отсутствует. LoginSDK имеет собственный процесс входа, loggingEnabled=false; AppMetrica не добавлена.

Текст ищется существующим сервисом только по действию пользователя, с названием/исполнителем/длительностью. Распознавание запускается явно: до 30 секунд потока запрашиваются у Яндекса, на устройстве строится отпечаток для Shazam, аудио не загружается туда и не сохраняется. Политика сети Яндекс Музыки не управляет страницей входа и внешними сервисами текста/распознавания.

## Проверка на телефоне

1. Войти из «Яндекс Музыка → Войти / аккаунт», попробовать LoginSDK; при отказе проверить сохранённую сессию и альтернативный вход.
2. Быстро переключить 5–10 песен, назад/вперёд, проверить обложки плеера и уведомления.
3. Открыть несколько собственных плейлистов, запустить загруженные песни, загрузить следующую страницу; проверить длительности в очереди.
4. Для онлайн-песни открыть «…», «Текст», «Определить песню», проверить результат поиска и сохранённый текст после переключения.
5. Включить только Wi-Fi, переключиться на мобильную сеть: дальнейшее чтение должно блокироваться; вернуть Wi-Fi и нажать воспроизведение. Отдельно проверить VPN и качество следующего трека.

CI не заменяет эти проверки на реальном устройстве и аккаунте. Аудиокэш, редактирование плейлистов сервиса, смешанные сохраняемые локальные/онлайн-плейлисты и lossless в этот комплект не входят. Звук остаётся на паузе.
