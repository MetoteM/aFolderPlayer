# AFP Online: границы модулей

Плеер → подписанный Binder-контракт IOnlineService → AFP Online → реестр коннекторов.

AFP Online устанавливается отдельно. Плеер проверяет подпись пакета dev.alex.afponline, а сервис защищён разрешением уровня signature. При отсутствии расширения предлагается перейти к обновлениям. Сейчас контракт API 1 возвращает только каталог возможностей: Звук помечен недоступным, без выдуманного входа или воспроизведения. Сетевых вызовов сервиса пока нет.

Будущий коннектор отвечает за авторизацию, возможности каталога и получение разрешённого потока; плеер сохраняет единое управление воспроизведением. До реализации нужно подтвердить пригодный способ интеграции Звука. Подписка и ограничения провайдера сохраняются. Отсутствие нашей аналитики не означает отсутствие обработки запросов самим провайдером. Пароли и токены не должны попадать в чат, GitHub или журналы.

## Совместимость каталога расширений

Новый клиент сначала запрашивает подписанный catalog-v2.json (schema 2). Только HTTP 404 разрешает переход к catalog.json. Ошибка подписи, откат версии или другая ошибка ответа не допускает обхода проверки через запасной каталог.

При публикации AFP Online издатель должен формировать и подписывать два каталога: catalog-v2.json со schema 2 и записями engine/model/online; catalog.json со schema 1 только engine/model для старых клиентов. Поля versionName и minimumPlayer описывают версию и минимальный код плеера. Пакеты и подписи APK дополнительно проверяются при установке.

Предварительная публикация 0.8.3-preview.1 содержит отдельный APK AFP Online без входа и воспроизведения. Она не публикует schema 2 и не заменяет стабильный каталог. Текущий публичный schema 1 продолжает работать через 404 fallback. Модель с прежним ID считается неизменяемой; обновлённая модель получает новый ID редакции. Неизменённые языковые архивы остаются в общем хранилище релизов и не перепаковываются.

## Решение по авторизации Звука

Согласовано: вход через Сбер ID, на стороне приложения Сбера или внешнего браузера; пароль в aFolderPlayer не вводится. До реализации необходимо зарегистрировать приложение и redirect URI, получить собственный client_id и подтвердить способ получения сессии/потока Звука. Сам по себе токен Сбер ID не считается разрешением на музыкальное API Звука. Чужие client_id, redirect URI и секреты не используются.

Документация: https://developers.sber.ru/docs/ru/sberid/service/overview и https://developers.sber.ru/docs/ru/sberid/service/reqdescription/authcodereq/mobile/reqmobile . Вход Звука: https://help.zvuk.com/article/42265 .

Планируемый UI: переключатель «Библиотека / Онлайн» в библиотеке, карточка «Звук», кнопка «Войти по Сбер ID», затем коллекция и воспроизведение через общий мини-плеер. Текущий APK содержит только вход в раздел из меню расширений; макет не является демонстрацией работающей авторизации.

Переход к стабильному выпуску расширения: реальный вход и возврат в приложение, проверка подписки, загрузка коллекции, реальный поток, пауза/следующий трек, фон/гарнитура, выход и отмена входа, восстановление после потери сети. До этого выпуск остаётся предварительным.
