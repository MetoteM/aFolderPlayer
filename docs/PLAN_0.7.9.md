# План 0.7.9: удобство библиотеки, определитель и поиск текста

Статус: подготовка, не опубликованный релиз. Базовая версия — 0.7.8.

## Первый пакет изменений

- Кнопка «Определить песню» в библиотеке и на экране проигрывателя; прежний пункт настроек удалён. Открытие экрана не включает микрофон: прослушивание запускается отдельным действием.
- Видимая кнопка обновления библиотеки.
- При добавлении папки в плейлист можно включить «Добавлять новые песни при обновлении библиотеки». Добавляются новые URI без дублей; порядок старых элементов сохраняется. Вручную удалённые песни автоматически не возвращаются. Привязка сохраняется при переименовании и удаляется вместе с плейлистом.
- Обновление активного источника добавляет новые песни в очередь с сохранением текущей песни и позиции.
- Неопределённая/некорректная длительность учитывается как ошибка чтения вместо молчаливого пропуска. Правило минимальной длительности 30 секунд сохраняется.

Старые импорты были снимками: восстановить исходную папку достоверно невозможно. Для автоматического пополнения существующего плейлиста нужно один раз повторно добавить нужную папку с включённой привязкой. Это исправляет подтверждённую причину отсутствия новых треков в плейлисте; отдельный случай отсутствия MP3 в самой библиотеке требует диагностики сканирования.

## Предлагаемый алгоритм определения названия и исполнителя

Не менять имена файлов и исходные теги. Хранить поисковые варианты и подтверждённую пользователем пару отдельно, для конкретного URI.

1. Проверить локальный текст и ранее подтверждённые поисковые данные.
2. Получить независимые подсказки: title/artist/albumArtist/album, имя файла, длительность. Пустые значения и заглушки не считать достоверными.
3. Осторожно нормализовать Unicode, невидимые символы, расширение, очевидные URL/доменные рекламные вставки, bitrate/codec и начальный номер трека. Не удалять все скобки, числа или пунктуацию: `99 Luftballons`, `AC/DC`, `P!nk`, `Live`, `Remix`, `Acoustic` могут быть значимыми.
4. Сформировать ограниченный набор гипотез: теги; исполнитель — название из файла; название без исполнителя. Обратный порядок — только при наличии признаков. Не пытаться определять песню только по имени исполнителя: это подсказка для отбора, а не достаточная идентификация.
5. Сначала запросить LRCLIB по лучшей паре, затем при необходимости по очищенному названию. Ответ search уже содержит метаданные и текст, поэтому отдельный предварительный запрос существования песни обычно лишний.
6. Оценивать совпадение названия, исполнителя, длительности, альбома и версии записи. Длительность сама по себе недостаточна. При опечатках допустимо ранжирование по сходству; короткие/распространённые названия требуют дополнительных признаков.
7. При отсутствии убедительного результата использовать один запрос MusicBrainz recording search с fuzzy-поиском, затем LRCLIB по исправленной паре. MusicBrainz — источник метаданных, не текста; соблюдать лимит и User-Agent.
8. Единственный однозначный результат можно открыть автоматически. При неоднозначности показать 3–5 вариантов с исполнителем, длительностью и версией; дать исправить запрос или перейти в определитель. Нельзя молча сохранять текст соседней песни.
9. Сохранять выбранную пару локально для следующего поиска. Общий механизм использовать для библиотечных треков и результатов определения.

Сетевые ограничения: не более трёх запросов LRCLIB и одного MusicBrainz на попытку; общий срок ожидания и отмена при смене трека/уходе; кеш отрицательных результатов с ограниченным сроком, ручной повтор. Не сканировать всю библиотеку через сеть и не отправлять аудио автоматически. Дополнительные поставщики текста пока остаются вне объёма.

Пример: `01__Rammstein - Sonne [320kbps] [site.example].mp3` даёт гипотезу `Rammstein / Sonne`; не удалять содержательные части похожих имён без проверки ответа.

Источники API: https://lrclib.net/docs ; https://musicbrainz.org/doc/MusicBrainz_API ; https://musicbrainz.org/doc/MusicBrainz_API/Search .

## Следующие QoL, по приоритету

1. Отчёт обновления: найдено, добавлено, пропущено, причины (короче 30 секунд, ошибка метаданных, утраченный доступ к папке). Пустой результат/ошибка доступа не должны выглядеть как успешное обновление.
2. Поиск и удаление в истории текста, объединённый доступ к сохранённым оригиналам/переводам; восстановление позиции чтения. Это сохраняет исходный объём дорожной карты 0.7.9.
3. Подтверждённые поисковые имена и ручное исправление запроса без переименования файлов.
4. Единые состояния ожидания, отмены, ошибки и повтора; сохранение результата и навигации при возврате.
5. Настройка привязанных папок существующего плейлиста и понятная индикация автоматического пополнения.
6. Отмена удаления из истории/плейлиста; сохранять различие удаления записи и удаления самого файла.

## Проверки перед выпуском

Автотесты привязки: новые файлы, дубли, другая корневая папка, вложенные папки, ручное исключение, переименование/удаление, статический импорт. Очередь: текущий трек/позиция/пауза/repeat не теряются. UI: кнопки доступны, пункт настроек убран. Для поиска: рекламные вставки, Unicode, корректные числа/пунктуация, опечатки, одноимённые песни, разные версии, отсутствие сети и отмена. Реальное добавление MP3 через Android-провайдер файлов и переходы экранов проверять перед публикацией; исключения предыдущих релизов не переносить автоматически.
