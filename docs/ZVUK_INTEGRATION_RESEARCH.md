# Звук: проверка интеграции до реализации

Дата: 15 октября 2026. Статус: исследование публичной документации и исходников, не проверка входа/стриминга с реальной подпиской.

## Вывод

Регистрация собственного приложения в Сбер ID не решает доступ к Звуку. Для релиза необходима либо подтверждённая партнёрская схема Звука, либо явно экспериментальная интеграция его веб-API с осознанно принятыми ограничениями. Обещать бесшовный вход через Сбер ID, автоматическое обновление сессии и стабильный стриминг по имеющимся источникам нельзя.

AFP Online и реестр коннекторов сохраняются. Реализацию конкретного входа пока не фиксируем как поддерживаемую функцию. Публичная 0.8.3-preview.1 остаётся основой расширения без реального входа и музыки.

## Подтверждённое и неизвестное

| Вопрос | Найдено | Следствие |
|---|---|---|
| Собственный Сбер ID | Официальная документация требует организацию, оферту через ЭДО, Client ID/Secret, сертификат и сервер партнёра | Это партнёрская интеграция, не простая регистрация APK. Банк выдает свою идентичность пользователя, а не музыкальную сессию Звука |
| События входа | На промышленном контуре обязателен запрос подтверждения успешного входа | Нельзя обещать полное отсутствие передачи событий провайдеру; это не тождественно рекламной аналитике внутри плеера |
| Вход самого Звука | Официальная помощь подтверждает Сбер ID; для подписки нужен связанный аккаунт | Входить надо именно в нужный аккаунт Звука, не создавать независимый профиль aFolderPlayer |
| Сторонние клиенты | Автор библиотеки zvuk-music использует токен веб-сессии Звука и X-Auth-Token; Music Assistant предлагает локальный ручной ввод токена | Это доказательство существующего неофициального подхода, но не поддерживаемого OAuth для стороннего плеера |
| Обновление сессии | В проверенном клиенте нет реализации refresh OAuth; документация провайдера рекомендует получить токен заново при истечении | Не назначать выдуманный срок жизни и не обещать автоматический refresh |
| Возврат из браузера | RFC 8252 отделяет хранилище cookies браузера от приложения | Открытие zvuk.com само по себе не передаст его сессию расширению. Нужен поддерживаемый callback/обмен; это ключевой неразрешённый участок |
| Каталог, коллекция, поток | Неофициальная библиотека реализует профиль, поиск, коллекцию и разрешение потока | Техническая основа существует. Без реального аккаунта не подтверждена работа для нашей сборки |
| Качество | README библиотеки и документация MA расходятся по доступности MP3 320 без подписки | Определять доступность по ответу сервиса/аккаунту/треку. Не обещать 320 или FLAC каждому |
| Ссылка на поток | В модели Stream есть expire/expire_delta; исходники различают прямые потоки и DRM-варианты | Хранить ID трека, получать свежую ссылку перед воспроизведением. Сам факт получения URL не доказывает воспроизводимость |
| Защита/ограничения | Клиент обрабатывает bot protection; официальная помощь отмечает возможную недоступность Сбер ID за пределами РФ или без SIM | Явные ошибки входа/сети/доступа, ограниченные повторы. Не обходить защиту и не объявлять любую ошибку отсутствием подписки |
| Официальный API для сторонних плееров | Открытого документированного SDK/договора с таким доступом в просмотренных источниках не найдено | Это не доказательство отсутствия партнёрского API. Требуется подтверждение Звука |

## Два направления

1. Партнёрский вариант: получить у Звука сведения о сторонних плеерах, авторизации и потоках. Уточнить, нужна ли собственная регистрация Сбер ID или Звук предоставляет свой согласованный вход. Предпочтительно для устойчивого массового релиза.
2. Экспериментальный вариант: сессия пользователя Звука через недокументированный веб-API. Ручной импорт токена пригоден только для отдельной диагностической сборки после согласования UX, а не подмена обещанной кнопки «Войти по Сбер ID». Нет оснований считать его стабильной поддерживаемой интеграцией.

Встраивать форму Сбера в управляемый нами WebView ради извлечения cookies не выбираем: RFC 8252 рекомендует внешний браузер для OAuth, а надёжная передача сессии всё равно не подтверждена. Чужие Client ID/Secret и подменённые redirect URI не используются. Отдельная регистрация в Сбер ID без ответа Звука сейчас преждевременна.

## Архитектура, которую можно сохранить при любом ответе

- AFP Online — необязательный отдельно подписанный APK; все особенности сервиса остаются в коннекторе.
- Разделить операции входа, проверки сессии, чтения каталога/коллекции и получения описания воспроизведения. Версионировать контракт возможностей; нынешний API 1 остаётся discovery-only.
- Состояния: не подключён, выполняется вход, подключён, требуется повторный вход, доступ ограничен, временно недоступен. Ошибка 403 не доказывает ни истечение сессии, ни отсутствие подписки.
- Долговременная сессия принадлежит расширению, хранится зашифрованно с ключом Android Keystore, не передаётся в чат, логи, GitHub, плейлисты или неявный Intent. Выход удаляет локальную сессию; серверный отзыв — только если подтверждён API.
- В очередь сохраняется ID трека и коннектора. Временный URI потока не является постоянной записью плейлиста. При истечении разрешается ограниченное повторное разрешение, без циклов авторизации.
- MediaSession, audio focus, Bluetooth, гарнитура, таймер сна и очередь остаются едиными в плеере. Коннектор не запускает второй проигрыватель.
- Формат, доступность качества, срок действия и DRM описываются отдельно. Защищённый поток без подтверждённого поддерживаемого пути не объявляется доступным; защиты не снимаются.
- HTTP загрузки расширений и HTTP музыкального стриминга — разные политики. Постоянный токен не уходит на CDN/чужой redirect; TLS обязателен. Списки доменов устанавливаются после проверки реальных ответов.
- По умолчанию нет фоновой синхронизации всей коллекции, постоянных опросов, предзагрузки нескольких треков и нового wake lock. Обложки/страницы кэшируются ограниченно; сеть работает по действию пользователя и потребности воспроизведения.
- Существующие исходники плеера и перевода не меняются для исследования. Языковые модели не перепаковываются.

## Что необходимо подтвердить у Звука

1. Доступен ли независимому некоммерческому Android-плееру официальный API/SDK и на каких условиях?
2. Есть ли авторизация аккаунта Звука через Сбер ID с возвратом в сторонний APK? Кто регистрирует Client ID и redirect URI?
3. Как выдаются, обновляются и отзываются именно токены Звука? Нужен ли сервер приложения?
4. Как проверяются подписка и права на трек, какие качества/форматы/DRM разрешены?
5. Какие события прослушивания/авторизации обязательны, что можно отключить? Допустим ли собственный интерфейс без рекламы?
6. Срок жизни потоков, лимиты запросов, одновременные устройства, география и требования к кэшированию?
7. Разрешены ли публикация открытого клиента и распространение независимого расширения?

Официальный канал поддержки указан на https://help.zvuk.com/article/42221 . Никаких писем/запросов от имени пользователя не отправлено. Ответа провайдера нет.

## Условия готовности

До выпуска рабочего коннектора проверяются на реальном аккаунте: вход именно в аккаунт с подпиской, возврат и отмена, перезапуск приложения, повторный вход после истечения, коллекция и поиск, фактическое декодирование потока и перемотка, смена трека и истечение URL, фон/гарнитура/потеря сети, выход и отсутствие секретов в журналах. Успешная сборка APK эти проверки не заменяет.
