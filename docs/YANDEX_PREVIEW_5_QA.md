# Онлайн-библиотека: плейлисты и общие действия

Ветка prerelease/yandex-spike. Плеер 0.8.4-yandex.5 (46), расширение 0.2.0-yandex.7 (10). Протокол расширения повышен до 3: требуется обновить оба APK из одного комплекта. Основная ветка не меняется. Установить оба APK поверх тестового комплекта с оригинальной подписью проекта.

## Поведение

Плейлист адресуется парой «владелец:номер». Собственные и добавленные плейлисты читаются отдельно и объединяются без дублей по этой паре. Ошибка optional-списка добавленных плейлистов не уничтожает собственный список. В каталоге есть явная кнопка «Открыть», состав, название выбранного плейлиста, ошибка с повтором и возврат к списку.

Нажатие песни или «Играть список целиком» в коллекции/плейлисте дочитывает оставшиеся страницы метаданных по 50 с прогрессом и отменой. Только после успешной подготовки плееру передаётся полная очередь. Отмена и ошибка не заменяют действующую очередь частичным списком. Каталог закрывается только после подтверждения приёма очереди сервисом плеера. При отказе экран остаётся открытым с явной ошибкой; название плейлиста передаётся в источник очереди. Аудио заранее не скачивается. Ограничения: 20 000 записей / 8 МБ метаданных; превышение сообщает об ошибке.

Поиск по загруженному списку работает локально. «В Яндексе» явно выполняет поиск сервиса (до 50 результатов). Сортировка — исходный порядок, название, исполнитель, длительность. При запуске полного источника фильтр и сортировка применяются ко всем полученным страницам. Повторяющиеся треки сохраняются как отдельные позиции.

Флажки/долгое нажатие включают выбор. «Действия» позволяет выбрать все показанные записи, снять выбор, воспроизвести выбранные, поставить далее, добавить в конец, добавить/убрать из избранного плеера, скрыть. Выбор показанных не означает загрузку ещё не открытых страниц. При добавлении далее/в конец действующий трек и позиция сохраняются; в пустой очереди начинается воспроизведение.

Избранное и скрытые доступны чере…1 tokens truncated…0437 ⋮. Они хранятся локально в рамках текущего аккаунта. Никакие лайки/дизлайки и изменения плейлистов Яндексу не отправляются. Кнопка ♥ в плеере работает с нашим избранным онлайн-песен. Скрытые исключаются из запуска и восстановления, а из текущей очереди удаляются слушателем локальной настройки. В разделе скрытых можно выбрать записи и вернуть их.

Рабочая очередь имеет отдельный сохраняемый снимок метаданных. Подготовка следующей операции больше не перезаписывает сведения об уже играющей очереди. Снимок сохраняет метаданные добавленных онлайн-треков, их порядок, дубли, позицию и обычные настройки повторения. Очередь может содержать локальные и онлайн-треки; собственные сохраняемые смешанные плейлисты — следующий этап.

LoginSDK и его кнопка убраны по решению пользователя. Остаётся подтверждённый вход через страницу Яндекса. Звук остаётся на паузе.

## Проверка

- Разбор ответов собственных и добавленных плейлистов с одинаковым номером у разных владельцев; 125 треков и границы страниц.
- UI: кнопка «Плейлисты» → «Открыть» → пятая песня → полная очередь 125 треков с индексом 4.
- UI: локальный фильтр, два флажка → играть далее → избранное → скрытие → возврат из скрытых без сетевых операций записи.
- UI: отказ сервиса принять очередь не закрывает источник и показывает ошибку.
- Сервис плеера: 125 песен, постановка далее и в конец, удаление скрытой, перезапуск с тем же порядком и длительностями.
- Отмена/зацикливание пагинации, повторы, независимые временные снимки, смена аккаунта.

Это воспроизводимые проверки с подставленными ответами API; они не подтверждают доступность любого плейлиста в реальном аккаунте. На телефоне нужно проверить собственный и добавленный плейлисты, переход 50 → 51, фон/гарнитуру, рестарт, скрытие текущей песни и пакетные действия. Не объявлять проверку на устройстве пройденной до результата пользователя.
