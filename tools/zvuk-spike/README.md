# Локальный эксперимент Звука

Ветка `prerelease/zvuk-spike`. Это диагностический инструмент для компьютера,
а не новый APK и не рабочая авторизация Android. Основная программа, AFP Translate,
ключ подписи, стабильный релиз и опубликованная предварительная версия не меняются.

Цель: проверить гипотезы до внедрения недокументированного API в расширение.
Не реализует Сбер ID, не извлекает cookies браузера, не обновляет токены,
не меняет коллекцию и не скачивает песни в библиотеку.

## Сценарий с аккаунтом

Используется только собственная существующая сессия Звука с согласия владельца.
Способ её получения описан автором стороннего провайдера:
https://trudenboy.github.io/ma-provider-zvuk-music/configuration/ .
Это экспериментальный ручной перенос, не поддерживаемая интеграция Сбер ID.
Токен вводится локально скрытым вводом; передавать его в чат, issue, GitHub или отчёт не нужно.

```sh
python3 tools/zvuk-spike/probe.py --track TRACK_ID --quality mid
```

Сначала подтверждаются неанонимный профиль и читаемость коллекции, затем разрешается
поток для указанного доступного аккаунту трека. В отчёте только состояния и hostname CDN,
без самого токена, профиля, ID/названий треков и полного подписанного URL.

После проверки принадлежности CDN можно явно разрешить этот hostname и проверить
короткий фрагмент локальным FFmpeg:

```sh
python3 tools/zvuk-spike/probe.py --track TRACK_ID --quality mid --cdn-host REVIEWED_HOST --decode-sample
```

Скачивается не более 2 MiB выбранного фрагмента в память с Range-запросом.
Если сервер не соблюдает ограничение размера, результат отклоняется.
Успех означает только декодирование доступного фрагмента до пяти секунд,
а не полное воспроизведение песни или проверку Android Media3.

`--token-file` допускает существующий локальный секретный файл ВНЕ репозитория.
Аргумента с самим токеном нет. На CDN токен аккаунта не передаётся.
Редиректы не выполняются, неизвестный CDN без явного разрешения не запрашивается.
Скрипт не обходит CAPTCHA, антибот или DRM; не делает автоматических повторов.
Использует настроенный системный HTTPS-прокси, если он присутствует.

## Проверка без аккаунта

```sh
python3 tools/zvuk-spike/probe.py --anonymous
python3 -m unittest discover -s tools/zvuk-spike -v
```

Анонимный запуск проверяет только доступность JSON endpoint профиля. Он не
подтверждает подписку, пользовательскую авторизацию или воспроизведение.

## Результат 15 октября 2026

- 8 модульных тестов пройдены локально: отсутствие токена на CDN/в отчёте,
  остановка после отказа сессии, отбрасывание анонимного/неполного профиля,
  HTML-защиты, ошибок GraphQL, небезопасных адресов, header injection и редиректов.
- Локально сгенерированный секундный MP3 успешно декодирован FFmpeg; неаудиоданные отклонены.
  Это проверка диагностического декодера, не музыки Звука.
- Прямое соединение из этой среды не установилось. Через системный сетевой маршрут
  запрос `/api/tiny/profile` получил HTTP 418. Причина (защита сервиса или сетевой
  посредник) не установлена. Защита не обходилась, повторных автоматических запросов нет.
- Авторизованный профиль, коллекция, выдача потока, декодирование музыки Звука,
  подписка, срок жизни сессии и Android-воспроизведение: **НЕ ПРОВЕРЕНЫ**.
- Собственного входа через Сбер ID и автоматической передачи сессии пока нет.

Следующее решение принимается после результатов с реальным аккаунтом и выяснения
поддерживаемого способа интеграции. Публичный массовый коннектор не выпускается
на основании только этих тестов. Исследование: ../../docs/ZVUK_INTEGRATION_RESEARCH.md .
